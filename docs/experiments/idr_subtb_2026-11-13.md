# Matched TB/SubTB charge guidance — 13 November 2026

**Stage:** completed by the user; results checked 13 November 2026. The protocol
below was fixed before execution. Configuration: `configs/idr-subtb.json`.

## Question and motivation

Can training on partial trajectories produce materially better charge guidance
than whole-trajectory balance, at the same frozen-ProGen sampling budget?

The [branch-rate result](idr_branch_rate_2026-11-12.md#completed-results--verified-13-november-2026)
produced 23 charge / 13 joint charge-disorder passes out of 384, versus ProGen's
20 / 10. Better explicit-context sensitivity has not translated into a useful
margin. Increasing evaluation alone would measure that margin more precisely;
it would not improve the generator. This experiment changes the training signal.

[Madan et al., ICML 2023](https://proceedings.mlr.press/v202/madan23a.html)
introduce SubTB constraints on partial trajectories using learned state flows.
Their convergence results motivate this test; their protein models, budgets and
tuned settings differ from ours. SubTB is not inherently guaranteed to beat TB on
a tree. Our diagnoses suggest noisy policy learning, not a proven unique cause.

## What stays fixed

Use the same eight inspected prompts, 16 supplied residues and 64 generated
residues, canonical 20-residue support, temperature 1, frozen float32 ProGen2-medium,
charge score and beta 2. The [charge protocol](idr_charge_2026-11-12.md) owns the
nominal charge definitions and thresholds: first/second half means +0.125/-0.125,
charged fraction 0.25, block tolerance 0.0625 and fraction tolerance 0.125.
Only the generated tail enters the charge reward. Disorder is evaluation-only.

Both methods use the same direct-context token head: normalized ProGen features
plus five charge/progress features and prompt identity, 128 hidden units with SiLU,
20 residual logits, and the zero-initialized 20-by-5 direct task matrix. All shared
parameters start identically for a given seed. Neither method resumes an old fit.

The source protocol is pinned to the completed context run using the manifest and
metric hashes in the new config. The old outcomes motivate this developmental
choice but are not used as the new TB control. All new prior/control sequences and
both trained policies are sampled afresh. Completed runs and historical source
modules remain unchanged.

## Formulation and implementation

The unchanged terminal target is

\[
R(x\mid c)=p_0(x\mid c)\exp(\beta S(x)),\qquad
\pi^*(x\mid c)=R(x\mid c)/Z(c).
\]

- `c`: the fixed 16-residue prompt; `x`: its 64-residue generated continuation.
- `p0`: frozen ProGen's conditional distribution, renormalized over the canonical
  residues at each generation step. It is also defined for a partial continuation.
- `S(x)`: the existing nonpositive charge-mismatch score; zero is a perfect match.
- `beta = 2`: fixed strength of the property tilt.
- `R`: unnormalized terminal reward, not a probability. `Z(c)` is its sum over all
  permitted continuations. `pi*` is the normalized target, not an exactly computed
  distribution in this enormous sequence space.

For a prefix state `s_t` after `t` generated residues, parameterize flow as

\[
\log F(s_t)=\log p_0(s_t\mid c)+g(s_t).
\]

`F` is the positive total flow through the prefix. `g` is its log value after
subtracting the known prefix log-prior. At the root, `g(s_0)=log Z(c)` is one learned
scalar per prompt. At the terminal state `s_T`, `g(s_T)=beta S(x)` is fixed by the
reward, with `T=64`. Only interior values come from a new scalar network. At an
exact solution, `exp(g(s_t))` equals the prior-conditional expected exponential
property score of future completions. It is not the raw expected charge or an
experimentally known reward for the partial sequence.

The token policy `q_theta(a_t | s_t)` is ProGen's logits plus the learned correction;
`theta` denotes its trainable parameters and `a_t` the next residue. For each
segment from prefix `i` to later prefix `j`, train the residual

\[
\delta_{i,j}=g(s_i)+\sum_{t=i}^{j-1}
\left[\log q_\theta(a_t\mid s_t)-\log p_0(a_t\mid s_t)\right]-g(s_j).
\]

Every sequence prefix has one parent, so backward probabilities are one. The
prefix log-priors cancel from the usual SubTB equation, giving the expression
above. This prior-factored parameterization is our algebraic choice, not an
additional reward or a claim copied from the paper. No prefix is scored as if it
were a completed IDR. No extra terminal ProGen pass is needed.

For each sampled trajectory use

\[
L_{\mathrm{SubTB}}=
\frac{\sum_{0\leq i<j\leq T}\lambda^{j-i}\delta_{i,j}^{2}}
{\sum_{0\leq i<j\leq T}\lambda^{j-i}},\quad \lambda=1.
\]

`L` is the loss, averaged across the batch; `lambda` weights segments by length.
With lambda 1 each of the 2,080 segments has equal weight. TB uses only the full
segment `i=0, j=T`, recovering the original loss exactly. SubTB's smaller raw loss
must not be read as improved accuracy: its averaging is different.

Cache detached ProGen features and logits during each on-policy rollout, recompute
the token-head probabilities once, predict scalar interior flows once, then use
cumulative log-ratios for all segments. Both endpoints receive gradients when
learned; terminal scores and ProGen remain fixed. Interior features are the states
**before** their next action, avoiding an off-by-one reward leak.

## Fixed settings and rationale

| Choice | Setting | Rationale |
|---|---|---|
| Methods and seeds | Fresh TB and SubTB, seeds 0/1/2 | Matched comparator; retain seed variability |
| Updates per fit | 800 | Bounded doubling of the earlier 400, equally for both methods; no convergence claim |
| Training batch | 8, one continuation per prompt | Preserve original data balance and memory use |
| Token MLP rate | 0.0001 | Preserve previous head optimizer |
| Direct task-matrix rate | 0.001 | Carry forward the bounded 10× setting, identically in both arms |
| Root log-normalizer rate | 0.01 | Preserve prompt normalizers |
| Auxiliary flow network | Separate LayerNorm + 128-unit SiLU MLP + scalar output | Same inputs/hidden width as the policy; no shared trainable weights |
| Flow initialization | Zero output; internal RNG seed 20000 + training seed | Initial residual flow is zero; cannot change token initialization or sample stream |
| Flow Adam rate | 0.001 | Engineering default for a new normalized-input scalar regression head, not a tuned optimum |
| Segment weighting | All segments, lambda 1 | Equal weight per segment, no selected horizon or lambda sweep |
| LR schedule | Multiply every group's rate by 0.1 after update 600 | Same 75% boundary as earlier experiments, scaled to 800 in both arms |
| Gradient clipping | Norm 1 jointly for policy + root normalizers; independently norm 1 for auxiliary flow | Preserve historical policy clipping without letting auxiliary norms consume that budget |
| Checkpoints/logs | Every 100 updates / every update | Retain diagnostic curves, optimizer/RNG state and rates; no checkpoint selection |
| Evaluation | 64 fresh continuations per prompt per seed per method | Fourfold earlier sample count, within the training comparison |
| Prior pool | 256 per prompt per seed, shared by both methods | Same 4× selection comparator; first 64 are raw prior draws |
| Random streams | Training 30000+seed, prior 40000+seed, final policy 50000+seed | Fresh and separated from past experiments; same stream across paired methods |

Adam defaults remain inherited (betas 0.9/0.999, epsilon 1e-8, no weight decay).
The scalar estimator and its separate clip/rate are required new optimization
choices; this is a comparison of two complete training methods, not literally a
single mathematical substitution with every optimizer dimension held constant.
On-policy paths diverge as policies learn; matched RNG does not mean identical
training examples after initialization. No replay buffer, exploration mixture,
reward change, beta sweep or ProGen unfreezing is introduced.

Total new work: six fits, **38,400 training trajectories**, **1,536 final outputs
per method**, and **6,144 shared prior proposals**. Both methods receive identical
ProGen forward/token budgets; SubTB adds small-head/segment computation. Attribute
shared pool generation once and report reuse explicitly. Approximate expected
runtime is 5–6 hours at the previous experiment's throughput; CPU scoring and GPU
hardware can change this. This is an estimate, not a measured new run.

## Evaluation and bounded decision

Automatically reuse the existing scorer/evaluator, including prior selection,
composition-preserving swaps, shuffled GFN tails, V3 disorder and V2 sensitivity,
per-prompt/seed breakdowns, repetition, diversity, prior log likelihood, charge
score and held-out full-trajectory residuals. Identical prior controls must agree
across methods. No disorder-based filtering or favorable-seed selection.

The primary practical endpoint is joint charge + isolated-tail predicted-disorder
success. Report charge success separately so disorder retention cannot hide failed
steering. Use common full-TB residuals as diagnostics, not a substitute for output
quality or an exact distribution-distance estimate. Save 100-update averages of
on-policy charge, score and losses; these are training curves, not validation
checkpoints. Final evaluation occurs only at update 800.

Predeclared engineering continuation screen: SubTB should exceed **both** matched
TB and raw ProGen by at least 5 percentage points in charge success and 3 points
in joint success, with nonnegative joint gains in all three seeds. Also require
pooled disorder and unique-tail fractions to fall by no more than 5 points versus
TB. These thresholds describe a practically useful development gain; they are
not significance tests or biologically validated standards. Report all results,
including mixed prompt outcomes, whether or not this screen passes.

- If SubTB clears the screen, assess repeatability/generalization before choosing
  a new biological property. Passing is not broad IDR-design validation.
- If both methods improve similarly, the extra budget may be useful; do not
  attribute that to SubTB.
- If loss improves but generation remains weak, stop this bounded comparison.
  Reassess target headroom, intermediate-flow learning and policy learning from
  the saved diagnostics before proposing another intervention. Do not default
  to a longer run, lambda/rate sweep or sampling-only exercise.

Stop at 800 updates. A numerical failure stops execution and records the error;
there is no silent retry, automatic extension, resume or overwrite. This fixed
setting's failure would not prove all SubTB formulations fail. The inspected
prompt panel remains development data. Charge is an exact nominal sequence
statistic; disorder is predicted, and neither is a measured functional property.

All six fits completed 800 updates; automatic evaluation finished. Total runtime
was 17,533.25 seconds (4 h 52 min 13 s). There are 1,536 raw final outputs per
method and 6,144 shared prior proposals. No seed or checkpoint was selected.

| Method | Charge passes / 1,536 | Joint passes / 1,536 | Isolated disorder | Unique tails |
|---|---:|---:|---:|---:|
| Raw ProGen | 65 (4.23%) | 28 (1.82%) | 66.3% | 95.7% |
| TB | 127 (8.27%) | 66 (4.30%) | 64.9% | 95.8% |

| Select best quarter of prior pool | 270 (17.58%) | 129 (8.40%) | 55.8% | 98.6% |

TB exceeds SubTB on charge and joint success in every trained seed. SubTB fails
the predeclared continuation screen. TB's absolute gain over raw ProGen is still
modest (+4.04 charge points, +2.47 joint points). Do not claim a clean causal effect
of doubling the old training budget: random streams and evaluation samples also
changed. Selection consumes four proposals per output; swaps change the sampling
distribution and have no evaluated edited-sequence prior likelihood. Neither is
an exact target-distribution comparator or a demonstrated efficiency win.

**Saved training/behavior diagnosis:** TB's policy gradient norm exceeded the clip
threshold on every update; SubTB did so on 10.1–10.9% of updates. SubTB's final
mean token KL to ProGen is about 0.00009 nats, versus TB's 0.00108. Its learned
block-specific corrections and task-branch norms are smaller. Held-out whole-TB
residual RMSE is 2.470 for SubTB versus 2.285 for TB. Thus smaller SubTB objective
values and less clipping did not imply better full-path consistency or steering.
This does not isolate the auxiliary flow estimator's accuracy or prove a specific
optimization cause. Fresh intermediate features were not retained for this run.

TB's mean first/second block charges are +0.0213/-0.0165; SubTB gives
+0.0143/-0.0022, versus the requested +0.125/-0.125. Both still steer weakly.
TB batches contain no fully charge-passing sequence on 55.9–60.0% of updates;
SubTB on 62.6–66.4%. Every batch nevertheless receives a continuous graded reward:
this is not a binary zero-reward problem.

### Post-hoc target-headroom estimate

Reweight the **unselected** prior pool within each prompt/seed by
`w = exp(beta * S)`, normalize those weights, then average the 24 group estimates
equally. The prior cancels because these proposals came from `p0`. With beta 2,
this estimates 24.65% charge and 11.35% joint success under the fixed target,
with mean score -0.7839. Across seeds, charge estimates span 21.84–26.15% and
joint estimates 10.29–13.05%. Effective sample sizes range 48–101 out of each
256-draw group, averaging 79.6.

These are finite-pool self-normalized importance estimates, **not** an exact
reachable rate, an upper bound, or proof about unseen sequence regions. They
suggest a meaningful target-fitting gap without first increasing beta. Estimated
disorder under this charge-only target is 56.4%, illustrating a tradeoff: even
perfect target fitting would not guarantee disorder retention or 100% charge
passes. Charge does not directly reward disorder.

### Proposed next intervention: replay-assisted TB

**Subsequently deferred:** the user requested a [reward audit](idr_reward_audit_2026-11-13.md)
before implementation. The proposal below is retained as its original rationale.

Keep TB, the frozen backbone, current token head and exact same reward. Change
how training trajectories are used: retain a prompt-balanced pool with useful
high-scoring examples and mix replayed trajectories with fresh on-policy draws.
The current code uses each batch for one update and discards it. Reuse gives
promising paths repeated training exposure; detached frozen features can be cached
without becoming stale when only the head changes.

This is a data-distribution/reuse hypothesis, not a diagnosis that missing replay
caused the failure. It is motivated by available high-scoring outputs, weak learned
steering and [GFlowNet language-model training with replay](https://proceedings.iclr.cc/paper_files/paper/2024/file/bc667ac84ef58f2b5022da97a465cbab-Paper-Conference.pdf)
(§3.3; see the targeted literature note). It changes the training method while
preserving its terminal objective. It is not inference-time selection or merely
copying selected sequences as the final deliverable.

Before implementation, pin buffer construction/sampling, diversity handling,
update/proposal budgets and a matched online-only TB control. Include buffer
construction and feature extraction in costs. Use fresh final-policy draws,
report copying/diversity as well as charge/disorder, and do not count this inspected
pool as held-out evaluation if reused for training. Do not combine replay with
unfreezing, a new reward, beta tuning or another objective change. If a bounded
replay comparison also lacks a useful gain, reassess policy capacity/formulation
rather than automatically expand the sweep. No new experiment is implemented here.
