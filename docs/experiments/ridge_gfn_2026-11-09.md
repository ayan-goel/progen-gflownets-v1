# Ridge-reward GFlowNet: controlled local rerun

**Status: user-run experiment complete; results analyzed 9 November 2026.**

## Question and rationale

Can the original trajectory-balance (TB) guidance learner realize the modest
measured-stability gain of the full-data ridge target? The
[predictor/reward study](predictor_reward_study_2026-11-03.md) found expected
measured stability 4.31965 for ridge at beta 1 versus 4.28005 for constrained
ProGen. These are exact target expectations, not trained GFN results.

In the meeting shared on 9 November, Tom prioritized training against the new
reward and checking training stability. Proceed with that controlled rerun before
the previously proposed split-robustness study. Do not interpret the old predicted
value near 3.97 as a measured-stability training plateau. The original GFN already
matched its original MLP target; the new question is whether it matches a more
useful target as well.

## Fixed inputs and changes

- Same 1O6X, original 204 evaluation identities, locally constrained ProGen prior,
  legal-action tree and cached prefix representations from runs/biological-first.
- Use saved runs/predictor-reward-v1/seed-0-n-950-ridge.pt, trained on all 950
  original training examples. Regularization penalty 10 was selected by validation
  RMSE. Seed 0 is an arbitrary representative, not the best outcome; full-data
  ridge repeats are essentially identical fits on the same data.
- Change terminal scores to ridge predictions. Preserve original score definition:
  predicted dG minus predicted reference dG, divided by training-label population
  standard deviation (1.177569 kcal/mol). Predicted reference = 4.113092 kcal/mol.
  No clipping, cap or extra normalization. Beta remains 1.
- The full-data ridge target is proportional to the frozen prior times exp(score).
  The GFN learns this target; ridge itself is not a sequence generator.
- Verify file hashes, candidate ordering, reference identity, training identities,
  and reconstructed ridge predictions before fitting. Reuse the saved prediction
  values after checking the checkpoint, avoiding CPU/GPU rounding changes.
- No new ProGen forward pass, predictor fitting or supervised-comparator fitting.
  Cache reuse is exact for this finite task; this is not a generation-speed claim
  for unconstrained new sequences.

## Training and evaluation choices

| Setting | Value and rationale |
|---|---|
| Guidance seeds | 0, 1, 2, inherited from the original pilot; same initialization procedure. |
| Guidance architecture | Original residual 128-hidden-unit head, zero output initialization; ProGen and predictor frozen. |
| Training | 20,000 on-policy TB updates, batch 64, Adam; inherited unchanged. |
| Learning rates | Head 0.001 and log-normalizer 0.01; multiply both by 0.1 after update 8,000. |
| Gradient clipping | Global norm 1; inherited. |
| Reward strength | Beta 1; isolate predictor change rather than selecting the largest inspected beta. |
| Monitoring | Existing exact predicted-target diagnostics at step 0, every 100 updates, rate transition and final step. No measured outcomes, stopping or checkpoint selection. |
| Checkpoint choice | Final update only for every seed. No early stopping, best-seed choice or retries selected by results. |
| Sample evaluation | Original 256 raw proposals, 32 selected slots; ProGen filtering uses 1,024 proposals. Post-selection is separate and not a matched-budget primary comparison. |

The resolved config copies all inherited optimizer and evaluation settings into
the new run. Monitoring is the sole training-time addition: it uses the existing
observational monitor, whose CPU tests establish unchanged updates/RNG. The
original pipeline's biological-monitoring guard remains unchanged; this dedicated
runner permits monitoring an already defined, inspected development target.

Primary outputs separate **expected predicted stability (ridge)** from **expected
measured stability (dataset dG)**. Both are exact probability-weighted means over
204 candidates. Compare ProGen, exact ridge target and each final ridge-GFN policy.
Also report TV/KL to target, log-normalizer error, probability of measured dG at
least reference, entropy-effective support, top-five mass and expected unique
count in 256 draws. Predicted-target fit curves diagnose optimization separately
from biological utility. Measured labels never enter the objective or monitor.

Historical original MLP-reward GFN policies are evaluated from their saved heads
on the same identities, without retraining. Their original measured expectation
was about 4.26975; they are distinct from the three MLP target fits in the newer
predictor study. Original raw outputs remain immutable.

## Interpretation and stopping

Completion means the fixed-budget run and evaluation finished, not that it passed
an automatic biological gate. Report all seeds and their target-fit errors. If
fit is close but measured utility does not improve, investigate the reported
expectations and reward/sampling definitions. If fitting is inaccurate or unstable,
inspect the fixed-target curves before changing architecture or objective.
The target gain is small and drawn from already inspected data. This cannot
establish broad generation or independent biological confirmation.

Next, after reviewing this run, define a controlled reward-noise study. Distinguish
fixed per-sequence corrupted rewards (a changed target) from per-query noise
(stochastic feedback): these test different failures. Noise levels and protocol
are not yet selected or implemented. SubTB, conditional-attribute formulations,
and partial ProGen fine-tuning remain separate research suggestions, requiring
primary-source review and a separate protocol; none is folded into this rerun.

## Command and artifacts

```bash
scripts/run.sh ridge-gfn --output runs/ridge-gfn-v1 --device cuda
```

Training and evaluation run together. Main report: runs/ridge-gfn-v1/report.md.
The run retains config, protocol/source snapshots, input hashes, scorer and task
copies, per-seed checkpoints/progress, cost records, exact comparisons and sampled
outputs. Existing output directories are rejected. On failure, status.json records

Read-only readiness check (no GPU or fitting):


literature optimum. No new literature review was needed for the unchanged TB rerun.


## Completed results

Run: runs/ridge-gfn-v1. Total wall time: 2,885.78 seconds (48 min 6 s).
All three seeds completed the prescribed 20,000 updates, with no checkpoint
selection or retraining. All pinned source-input hashes still match. A read-only
CPU reconstruction from the saved heads reproduces the reported measured
expectations exactly. [Analysis evidence](../verification/ridge-gfn-results-2026-11-09.json)
records aggregates, sampled outcomes and selected training-curve observations.
No original run artifacts were modified.

### The trained GFN realizes the ridge target's local gain

All stability values below are **expected measured stability**, in kcal/mol:
experimental values weighted by the corresponding policy's sequence probabilities.
They are not predictor estimates or new wet-lab measurements.

| Distribution | Expected measured stability | TV to ridge target |
|---|---:|---:|
| Constrained ProGen | 4.28005 | 0.190009 |
| Original MLP-reward GFN, historical seed mean | 4.26975 | Not compared here |
| Exact ridge target | 4.31965 | 0 |
| Ridge GFN, seed 0 | 4.31977 | 0.000412 |
| Ridge GFN, seed 1 | 4.31965 | 0.000227 |
| Ridge GFN, seed 2 | 4.31918 | 0.001367 |
| Ridge GFN, seed mean | **4.31953** | — |

Mean gain is +0.03948 over ProGen and +0.04978 over the original MLP-reward
GFN. All seeds improve over both historical baselines. The seed-mean target gap
is −0.00012, so the small local gain calculated in the predictor study is now
realized by trained policies. This is repeated optimization on one fixed reward
and support, not three independent biological replications.

For clarity, the new report also contains **expected predicted stability under
ridge**: 4.14996 for ProGen, 4.34509 for the ridge target and 4.34509 for trained
GFNs on average. The old MLP's approximately 3.973 prediction is a different
predictor's estimate and must not be compared with measured values as a gain.

Reference-level success probability rises from 83.95% for ProGen to 87.06% for
trained GFNs (target: 87.09%). The price is modestly lower diversity: expected
unique sequences per 256 draws falls from 10.67 to 9.87. GFN raw batches contain
11/9/10 unique variants versus ProGen's 13/11/12. This remains concentrated
sampling within the same 204 measured candidates, not broad novel generation.

### Training reliability on this task

- Initial TV is 0.1900 for every seed. All first reach logged TV below 0.05 at
  step 100; at step 1,000, TVs are 0.001995 / 0.000275 / 0.003335.
- Final checkpoints all closely match the target. Across logged observations in
  the last 4,000 updates, the largest TV is 0.00420. There are fluctuations but
  no evidence of sustained divergence at those observations; this does not assert
  every unlogged update was equally accurate.
- Final loss values are 6.13e-7 / 3.77e-7 / 2.97e-5. Loss alone is not used as
  convergence evidence; the full-support probability comparisons establish fit.
- Each seed takes about 15.8–16.2 minutes. Exact monitoring adds roughly 1.4 s per
  seed. No backbone or scorer-fitting work occurs during training.

The 20,000-step budget was deliberately unchanged. Early good fits suggest room
for a smaller future budget, but this run does not retroactively change the
stopping rule or establish a sufficient budget for noisy rewards.

### Next decision: controlled reward-noise sensitivity

Keep this completed run as the clean ridge baseline. The next experiment should
first specify fixed per-sequence noise on the dimensionless predicted score,
independent of evaluation labels, then compare two effects separately:
(1) corrupted target versus clean target and its measured utility;
(2) trained GFN versus the corrupted target it was actually asked to learn.
Use predeclared noise levels/seeds and retain the original beta and support.
Do not pick noise realizations by biological outcomes. This is a controlled
sensitivity model, not a claim to reproduce real assay noise.

Fresh noise on every reward query would be a different experiment and should not
be silently mixed with fixed score corruption. No noise grid or new training
implementation has been selected during this analysis. TB remains appropriate
for the immediate baseline; these results do not motivate simultaneous changes
to backbone training, attribute conditioning or the GFN objective.
